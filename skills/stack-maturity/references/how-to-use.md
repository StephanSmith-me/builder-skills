# How to use this

The comparison is in `SKILL.md`. This file is what the lump is for.

## Point, then stop

Use this when an assessment should say where time went. One thick area, one thin area, one signal. Do not walk every skill in the library. Do not turn the note into a rebuild plan.

The person using it can see time across projects, or a builder going down a blind alley. You point at the lump. You do not start the missing work.

## What a lump is

A lump is uneven maturity. One area is ahead of the stage. Another area the stage needs is thin.

The example to trust: secrets are complex and overbuilt, and Supabase has no migrations. Time went into secrets. The schema was left as manual edits. That is the signal. It is not a score.

## What it is not

- It is not a percent, a grade, or an hour estimate.
- It is not proof of who wrote the code. Do not name a person. Do not run blame to force a cause.
- Two fitted areas are not a lump. Say the stack is even.
- A missing tool the project does not use is not the thin area. No Supabase means there are no missing migrations to report.
